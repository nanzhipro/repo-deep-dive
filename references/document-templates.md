# Document Section Templates

> Phase 4 (Structured Write-Up) 中,每篇产出文档的章节骨架。
>
> 用法:开新文档时,从这里 copy 对应类型的骨架,把素材填进去。
>
> ⚠️ **特别提示** —— 三类核心文档/收尾产物有专门约定,不完全依赖下面模板:
>
> - **Layer 4 文档**(`M+2-mindset-and-philosophy.md`):见 [mindset-extraction.md](./mindset-extraction.md) 末尾的模板
> - **Layer 5 文档**(`M+3-apply-and-creation.md`):见 [internalization-and-creation.md](./internalization-and-creation.md) 末尾的模板
> - **最终概念表**(`concept-table.md`):统一收录共享概念,承接跨文档 wikilink 导航
>
> 这三类比下面 8 种结构模板更重要 —— 它们是 Skill 的核心产物。

## 通用质量要求(所有文档)

每篇文档都先满足 GitHub Markdown 的格式约束,再做内容层自检。

### GitHub Markdown 最佳实践检查单

- [ ] 只有 1 个 H1,其余标题按 `##` / `###` 递进,不跳级
- [ ] 标题、段落、列表、表格、引用、代码块之间留空行
- [ ] 所有 fenced code block 都标 language(`bash` / `json` / `yaml` / `text` / `mermaid` 等)
- [ ] 对比优先 Markdown 表格;只有目录树、ASCII 图、对齐示意图才用 `text` 代码块
- [ ] 链接优先相对路径 Markdown link,不裸写“见某文件某处”
- [ ] 除 GitHub Markdown 无法表达的场景外,不使用原生 HTML

### Learning in Public 检查单

- [ ] 开头明确交代:面向谁、要解决什么问题、最重要的结论是什么
- [ ] 不假设读者知道作者脑中的上下文;首次出现的缩写、术语、内部抽象都做一句解释
- [ ] 标题写成可被单独分享和引用的形式,避免私聊式标题
- [ ] 结尾给出可复用 takeaway / 下一步 / 公开可讨论的问题
- [ ] 整篇默认可直接提交、分享或发布,不出现临时备忘式语气

### 内容质量自检

- [ ] 体量适中(每篇 2000-5000 字,信息密度 > 灌水)
- [ ] 至少 5 处 `path:line` 引用
- [ ] 至少 1 张图(架构 / 流程 / 对比表)
- [ ] 至少 2 个 ✅/❌ 对比例子
- [ ] 结尾有 "复用清单" 或 "下章预告"
- [ ] 共享概念若会在 ≥ 2 篇文档重复出现,首次出现处补 `[[concept-table#<Heading>|<Alias>]]`;若需要 GitHub 兼容,并排补普通 Markdown link

## 类型 0:concept-table.md(最终汇总 + 概念导航)

```markdown
# Concept Table · 最终汇总与概念导航

> Final synthesis · 统一共享概念入口 · 其他文档通过 `[[concept-table#<Concept Heading>|<Alias>]]` 回链到这里。

## Final Synthesis

<用 200-400 字总结:最值得带走的抽象 / mindset / transfer 机会>

## 使用约定

- 只收录会在 2 篇以上文档复用的概念(建议 8-20 个)
- 概念标题尽量用稳定、可 slug 的短英文短语
- 其他文档第一次出现共享概念时,补 `[[concept-table#Trust Boundary Isolation|Trust Boundary Isolation]]`
- 若需要 GitHub 兼容,并排保留 `[Trust Boundary Isolation](./concept-table.md#trust-boundary-isolation)`

## Concept Index

- <path:line>

- [02-architecture.md](./02-architecture.md)

**相关概念** · <TODO>

```

## 写作禁忌

❌ "总之" / "综上所述" / "首先...其次...最后" — 中学作文范式
❌ "这是一种非常好的设计" — 没说为什么
❌ "可以考虑..." — 优柔寡断,直接说"建议 X 因为 Y"
❌ "众所周知" — 假设读者知识
❌ "一句话总结" 后跟 5 句话 — 自相矛盾
❌ 每章都重复贴 README 的内容 — 浪费 token
❌ 把并行研究线程或子代理的报告直接 paste — 没消化的素材是垃圾

## 写作偏好(高质量产出)

✅ **每段一个 idea** — 不要 1 段 200 字塞 4 个观点
✅ **数字 / 路径 / 字面引用** 优先于形容词
✅ **表格 > 段落**(对于结构化对比)
✅ **图 > 表格**(对于多对多关系)
✅ **反例对比** > 单边描述
✅ **箭头表达流程**(→ 比"然后"清晰)
✅ **黑体强调名词** 而不是动词
✅ **代码块标 language** — 让 GitHub 预览、语法高亮、复制体验都稳定
